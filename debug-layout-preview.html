你的设想 · 梳理

👤 给人用的通道

  • relay-c 网页：手动点复位、进烧录模式、看状态
  • ssh-bridge 网页：Dashboard 查看串口执行状态、配置通道
  • SSH 连串口：PuTTY / ssh.exe 登录本地映射端口，人工交互 Shell
  • SSH 跳板 → 板卡网口：板子起来后，连板载 Linux 的 SSH（以太网）

🤖 给 AI Agent 用的通道

  • relay-c HTTP API：curl 触发上电/断电/reset/upgrade_mode
  • ssh-bridge 串口 HTTP 接口：发指令、读输出，无需交互式 TTY
  • AI 可跑在接板子的调试主机，也可跑在远程服务器
  • 远程 AI 通过 HTTP 调调试主机上的 relay / bridge 接口，实现分布式控板

核心思想：板子和AI Agent都可以物理分离；relay 管「电源与时序」，ssh-bridge 管「串口数据面」； 人走 Web / 交互 SSH，AI 走 HTTP API；人可随时打开网页旁观串口状态，与 AI 自动化并行。

1 角色与接口分工

同一套服务，不同入口服务不同角色。relay 管硬件时序，ssh-bridge 管串口数据；HTTP 归 AI，Web/SSH 归人。

人 AI Agent relay-c ssh-bridge-c 板卡/继电器

2 分布式部署拓扑

AI Agent 可在调试主机本地运行，也可在远程服务器；远程 AI 通过 HTTP 调调试主机 API。人与 AI 均可分布式，板卡只需物理连接到调试主机。

人（可远程） AI（可远程） 调试主机 板卡网口

3 典型协同链路（AI 自动化 + 人旁观）

一次完整分布式调试的时间线：AI 走 HTTP 闭环，人随时 Web 看串口状态，必要时 SSH 介入或跳板登录板载系统。
